# 笔记修改

对资料库中已有的 Markdown 笔记进行内容修改。所有修改通过 edit_file 工具完成，支持查找替换、追加内容和整体改写三种操作。

## 工作方式

1. **先读后改**：修改前必须用 grep_chunks 或 list_knowledge_chunks 读取目标文件的当前内容，确认要修改的具体位置和文本；不得凭猜测直接写入。
2. **最小变更**：优先使用 replace（查找替换）做精确修改，避免整体改写引入意外变化。只有用户明确要求重写全文时才用 overwrite。
3. **确认匹配**：replace 操作的 old_string 必须是文件中唯一的片段。如果匹配到多处，先向用户确认目标位置，或提供更长的上下文片段使匹配唯一。
4. **保留结构**：修改时保留文件的 frontmatter、标题层级、列表格式等结构；只改动用户要求修改的部分。

## 操作选择

| 场景 | 操作 | 说明 |
|------|------|------|
| 修改某段文字 | replace | 提供 old_string + new_string |
| 在文末补充内容 | append | 提供 content |
| 整体重写文件 | overwrite | 提供 content（新全文） |

## 修改原则

- **精确替换**：old_string 应包含足够的上下文以确保唯一匹配，但不要包含无关内容。
- **格式一致**：新内容的 Markdown 格式（标题层级、列表符号、代码块风格）应与文件现有格式保持一致。
- **不动 frontmatter**：除非用户明确要求，不要修改文件头部的 YAML frontmatter。
- **分批修改**：单次 content 不超过 30,000 字符；超长文件的修改应拆分为多次 replace/append 操作。

## 输出规范

修改完成后简要说明：
1. 修改了哪个文件
2. 做了什么类型的修改（替换/追加/改写）
3. 修改的关键内容摘要

不需要重复展示整个文件内容——用户可以在编辑器中查看。

## 安全边界

- 不删除文件、不移动文件、不重命名文件。
- 不修改 `.menghan-meta` 目录下的任何文件。
- 不修改非 Markdown（.md）文件。
- 多处匹配无法确定时，停下来问用户，不擅自选择一处替换。
- 用户未要求修改的内容一律保持原样。
