# notice-hub（群务台）使用与维护

> 面向最终用户：如何安装、配置、使用和排障 Trellora 的 notice-hub（群务台）同步插件。
> 接口契约与映射规则见 [notice-hub 插件化与日程适配方案](notice-hub-插件化与日程适配方案.md)；插件包自身的开发说明见 `plugins/notice-hub/README.md`。

**notice-hub（群务台）** 从 QQ 群（及钉钉/微信/学习通）读取消息，过滤闲聊，提取通知、行动项与截止时间，生成待办与日历订阅。Trellora 插件把其中的通知、待办与截止时间**同步进 Trellora 日程**，让你在日/周/月/年视图、待办面板与提醒体系中直接看到群通知衍生的日程。

V1 只做单向同步：notice-hub → Trellora。在 Trellora 内勾选完成不会回写 notice-hub（列入 V1.1）；notice-hub 收件箱（待确认消息）不会导入日程，避免打扰。

## 1. 安装

### 前置条件

1. Trellora 1.3.0 或更高版本（插件清单 `engine.trellora >= 1.3.0`）。
2. 本机运行的 notice-hub 服务（Python 3.12+，Web 待办台默认端口 8766）。Trellora 不代管该服务；服务的安装与运行见 notice-hub 上游仓库。
3. notice-hub 侧配置 `QQ_DIGEST_WEB_TOKEN`（访问令牌）时，安装插件后需要填入同一令牌。

### 方式一：从 GitHub Release 安装（推荐）

1. 打开「设置 → 插件管理」。
2. 在「插件下载地址」粘贴 notice-hub 插件包的 GitHub Release URL（`.../releases/download/.../plugin.zip`），点击「安装」。
3. 安装完成后在插件列表中启用 **群务台 · notice-hub 同步**（`com.expertkt.notice-hub`）。

### 方式二：本地 zip 安装

插件宿主提供本地 zip 安装（`plugin:install-from-zip`）：插件包根目录需包含 `plugin.json`（可以在顶层，也可以在唯一子目录内）。当前设置界面只提供 URL 安装入口；命令面板或后续版本会补充本地 zip 入口，届时选择下载好的 `notice-hub-<版本>.zip` 即可。

### 方式三：开发目录安装

开发或调试时，直接把 `plugins/notice-hub/` 整个目录复制到应用插件目录 `<应用配置目录>/plugins/notice-hub`（macOS 一般为 `~/Library/Application Support/<应用名>/plugins`，Windows 为 `%APPDATA%\<应用名>\plugins`；实际路径以「设置 → 关于与诊断」显示的配置目录为准），重启应用后即被发现。目录内必须保留 `plugin.json`、`main.js`、`lib/` 以及 `LICENSE`、`LICENSE-UPSTREAM`、`NOTICE` 三个许可证文件。

### 授权（L2 权限）

首次启用插件时会弹出授权对话框。本插件需要：

| 权限 | 用途 | 不授权的后果 |
|---|---|---|
| `system:network` | 访问本机 notice-hub 服务（http 环回地址） | 同步失败，状态条显示连接错误 |
| `system:file` | 在插件存储目录读写同步快照缓存 | 断网降级与去重能力不可用 |
| `schedule:write`（L1） | 把同步结果写入日程库 | 无法创建日程条目 |
| `ui:command`（L1） | 「同步群务台」「重置群务台缓存」命令 | 无法手动触发同步 |

网络策略仅放行 **环回地址（127.0.0.1 / localhost）的 http** 与 **https**；内网 IP、公网 IP 的 http 一律拒绝，令牌不会拼进 URL 或写入日志。

## 2. 配置项说明

打开「设置 → 群务台（notice-hub）」，修改后点击「保存配置」。配置保存在应用配置目录的 `notice-hub.json`；保存后立即下发给插件。

### 连接

| 配置项 | 字段 | 默认值 | 说明 |
|---|---|---|---|
| 启用群务台同步 | `enabled` | 关闭 | 关闭后不再同步；已同步的日程条目保留在日程库中 |
| 服务地址 | `baseUrl` | `http://127.0.0.1:8766` | 仅允许环回地址的 http 或 https；不允许内嵌账号密码 |
| 访问令牌 | `token` | 空 | 对应 notice-hub 的 `QQ_DIGEST_WEB_TOKEN`，以密码框输入防肩窥；留空表示不设置令牌（仅环回地址可用） |

### 同步选项

| 配置项 | 字段 | 默认值 | 说明 |
|---|---|---|---|
| 同步间隔（分钟） | `syncIntervalMinutes` | 15 | 5–240 的整数；过密会增加打扰与日志噪音 |
| 同步待办 | `includeTodos` | 开 | 把群通知衍生的任务导入待办面板与日历 |
| 同步公告 | `includeNotices` | 关 | 把群公告以全天事件导入日历（易打扰，默认关） |
| 清理远端已删除的条目 | `pruneMissing` | 关 | 开：远端消失的条目下次同步时从日程库移除；关：保留本地副本 |
| 日程分类名称 | `categoryName` | 群务台 | 同步条目归入的日程分类，侧栏可按分类筛选 |
| 提醒提前量（分钟） | `reminderOffsetsMinutes` | `1440, 0` | 逗号分隔的非负整数（最多 8 个，单个 ≤ 43200）；`1440, 0` 即「提前 1 天 + 到点」；留空表示不生成提醒 |

「立即同步」按钮使用**已保存**的配置立即执行一次同步；修改配置后请先保存再同步。同步进行中（状态为「同步中」）按钮会禁用。

### 状态条

| 显示项 | 含义 |
|---|---|
| 状态徽标 | `disabled` 已禁用（灰）/ `idle` 空闲（次强调）/ `syncing` 同步中（主色、脉冲）/ `ok` 正常（绿）/ `error` 错误（红） |
| 上次同步 / 上次成功 | 最近一次同步的开始与最近一次成功时间 |
| 下次同步 | 按同步间隔推算的下次定时同步时间 |
| 服务可达 | 最近探测到 notice-hub 服务是否可达 |
| 已同步计数 | 待办 / 公告 / 跳过（本地已完成或取消、被冲突规则跳过的条目） |
| 最近错误 | 红字展示，给出可操作的中文修复提示 |

## 3. 使用流程

1. 启动本机 notice-hub 服务（默认 `http://127.0.0.1:8766`）。
2. 安装并启用插件，完成 L2 授权。
3. 在「设置 → 群务台（notice-hub）」填写服务地址与访问令牌，打开启用开关，点击「保存配置」。
4. 点击「立即同步」，观察状态条：显示「正常」且计数非零即成功。
5. 打开日程视图或待办面板查看结果（见下一节）。日后的同步按间隔自动进行，无需手动操作。
6. 需要清理本地同步快照并全量重同步时，运行侧栏命令「重置群务台缓存」。

## 4. 日程界面效果

- **日/周/月/年视图**：同步条目归入分类「群务台」（默认色 `#0F766E`），与手动创建的日程同视图展示、可正常点击编辑。
- **来源徽标**：来自群务台的条目在月视图事件芯片与待办行上显示小型铃铛徽标，悬停提示「来源：群务台 · 来源群：<群名>」，读屏可识别（`aria-label="来源：群务台"`）。辨识完全复用条目 `tags`（含 `notice-hub` 标记），不新增任何数据通道。
- **待办面板**：任务按截止日期分组（已过期/今天/本周日期/无截止），优先级映射为紧急/高/普通/低徽标。
- **时间映射**：带时刻的截止时间生成 1 小时长度的事件；纯日期生成全天条目；无截止时间的条目只进待办面板。
- **状态映射**：notice-hub 的 `open`/`candidate` 映射为待办「待处理」（`candidate` 标记为暂定），`done` 映射为已完成，`dismissed`/`expired` 映射为已取消。
- **提醒**：对带截止时间的条目按「提醒提前量」生成提醒（默认提前 1 天 + 到点），同时走系统通知与应用内提醒。
- **来源群与原文**：条目描述中保留行动内容、来源群、发送者与原文摘录；`tags` 中含群名、`待确认`、`置顶`、`公告` 等标记，可在日程侧栏按标签筛选。

同步条目可以被正常编辑、删除；它们只是普通日程条目，删除后不会被重建（远端再次变化且映射表已清理时除外，属预期行为）。

## 5. 排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 状态「错误」，提示无法连接群务台 | notice-hub 服务未启动，或端口不是 8766 | 启动服务；核对「服务地址」；确认服务在本机（环回）监听 |
| 状态「错误」，提示未授权或 401 | 访问令牌缺失或与 `QQ_DIGEST_WEB_TOKEN` 不一致 | 重新填写令牌并保存；确认 notice-hub 侧令牌已启用；令牌为空时服务端只允许环回来源 |
| 同步「正常」但计数为 0、日程里没有条目 | 群内确实没有提取到任务/公告；或只开了公告而公告默认不进日历 | 在 notice-hub Web 待办台确认任务存在；打开「同步待办」；需要公告时打开「同步公告」再同步 |
| 条目在 Trellora 里被删掉 | 开启了「清理远端已删除的条目」且远端确实已删除/撤回 | 不希望自动清理就关闭该选项；历史条目可从备份恢复 |
| 手动删除的条目又回来了 | 远端任务重新变化且映射表已清理，被当作新条目重建 | 属预期；在远端把任务置为完成/取消，或保留本地条目不删 |
| 提醒没有触发 | 条目没有截止时间，或「提醒提前量」留空 | 为条目设置截止时间；提前量填 `1440, 0` 之类数值 |
| 同步很慢或日志频繁 | 同步间隔设置过密 | 把同步间隔调回 15 分钟以上 |
| 启用插件时没有弹授权 / 同步一直失败 | L2 权限（system:network）被拒绝 | 在插件管理中禁用再启用插件，重新授权 |
| JSON 接口异常但服务仍在 | notice-hub API 版本变化 | 插件会自动回退解析 `/calendar.ics`（仅带截止时间的条目）；仍失败则升级插件或核对服务版本 |

错误信息都以中文可操作提示显示在状态条「最近错误」中；排查时可同时查看「设置 → 关于与诊断 → 日志目录」中的应用日志（搜 `PLUGIN:com.expertkt.notice-hub`）。

## 6. 隐私说明

- 同步到的通知、待办与日程只写入**当前工作区**的 `.menghan-meta/schedule/schedule.db`，不会上传到任何外部服务器。
- 访问令牌只经 `X-Token` 请求头发送给本机 notice-hub 服务，**不写入**日志、缓存文件、状态载荷或命令行；设置界面用密码输入框展示。配置文件 `notice-hub.json` 中的令牌以系统安全存储（safeStorage）加密保存，不以明文落盘。
- 群消息摘录（行动内容、原文片段）会进入本地日程库，请按个人数据保管；完整工作区备份会包含这些内容。
- 同步快照缓存只保存在应用插件存储目录，不含令牌；「重置群务台缓存」可随时清除。

## 8. 维护与升级

- **升级插件**：在「插件管理」中卸载旧版本后按第 1 节安装新版 zip（开发目录方式直接替换 `<应用配置目录>/plugins/notice-hub` 目录）。升级会保留配置文件 `notice-hub.json`；如需干净状态，先运行「重置群务台缓存」。
- **升级 notice-hub 服务**：按上游仓库说明升级。插件对字段缺失有容错（缺字段的条目跳过并计入「跳过」计数），API 形态变化时自动尝试 ICS 兜底；大版本升级后建议先「立即同步」验证。
- **配置备份**：`notice-hub.json` 随应用配置目录管理；完整工作区备份包含日程库但不包含令牌明文的导出承诺请以实际备份说明为准（见 [下载、备份与换电脑](桌面分发与备份恢复使用说明.md)）。
- **常见维护动作**：换令牌 → 改「访问令牌」保存；换端口 → 改「服务地址」保存；停止同步 → 关闭「启用群务台同步」保存；清理本地同步结果 → 关闭插件或用 `pruneMissing` 与手动删除。
- **验证脚本（开发者）**：`node scripts/verify/verify-notice-hub-plugin.mjs` 校验归一化、ICS 解析、缓存与端到端同步；`pnpm run verify:plugin-system` 校验插件系统扩展点。日常使用无需运行。
- **V1 边界**：不支持双向回写、不导入收件箱（待确认）、无多来源过滤器；这些在路线图（契约 §11）中另行安排，升级前请阅读版本说明。
